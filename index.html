앱 사진 · 실물 사진 비교

앱에 등록된 사진과 각 식당이 올린 실물 사진을 나란히 놓고 확인합니다.
하루치를 리포트로 출력한 뒤 과거 사진을 정리합니다.

01관리자 키

식당 저장소에 접근할 수 있는 키를 입력하세요. 이 기기에만 저장됩니다.

01오늘 현황 조회 전용

기록 저장소에 접근할 수 없는 키입니다. 맡은 식당의 현황만 조회할 수 있고, 기록·정리 기능은 쓸 수 없습니다.

인쇄 창이 열리면 대상을 PDF로 저장을 고르세요. 한 번 고르면 다음부터 그대로 열립니다.

02사진 비교 왼쪽이 앱 등록 사진, 오른쪽이 올라온 실물 사진입니다.

빈 자리를 누르면 사진을 올리고, 사진 위 ↻ 로 다시 올리고 × 로 지웁니다. 지운 사진은 되돌릴 수 없습니다.

03미업로드

    04누적 현황 사진이 정리된 뒤에도 이 기록은 남습니다.

    일자별 업로드율
    전체 업로드율
    식당별 업로드율 (조회 월 누계)

    05운영 · 기록 저장소 용량과 남은 호출 한도입니다.

    기록 남기기 — 매일 누릅니다. 어제까지의 날짜별 업로드 수를 기록 저장소에 남깁니다. 사진은 그대로 둡니다.
    과거 사진 삭제 — 지울 때만 누릅니다. 사진이 남아 있으면 지난 날짜도 조회하고 리포트를 다시 뽑을 수 있습니다.

    보관 정책과 한계
    1. 사진을 지워도 저장소 용량은 줄지 않습니다. git 이 히스토리에 그대로 들고 있어서, 보이는 파일이 오늘치뿐이어도 용량은 같은 속도로 늘어납니다.
    2. 지워진 사진도 당분간 커밋 주소로 꺼낼 수 있습니다. 완전 폐기는 분기별 저장소 재생성 시점에 이뤄집니다.
    3. 그래서 기록과 삭제를 갈라 뒀습니다. 기록은 매일, 삭제는 필요할 때. 사진을 남겨 두면 분기 안에서는 지난 날짜 리포트를 다시 뽑을 수 있습니다(메뉴 API 가 과거 날짜 메뉴를 3개월쯤 돌려줍니다).
    4. 그러므로 "사진이 당일 폐기된다"고 외부에 약속하지 마세요.
    5. 저장소가 500MB를 넘으면 재생성을 검토하세요. 재생성 후에는 식당별 키를 다시 발급해야 합니다.
    6. 업로드 기록은 "어느 식당 저장소에 들어왔는가"까지만 신뢰할 수 있습니다.
